# taste Agent Guide

This repository defines the `.taste` file format and its implementations. Read `README.md` and
`spec/SPEC.md` before changing behavior. Machine-specific notes belong in an untracked
`AGENTS.local.md`; read it when present.

## Layout

- `spec/SPEC.md` — the format. It is the source of truth; implementations follow it.
- `spec/taste.schema.json` — JSON Schema (draft 2020-12) for `taste.json`. Referential rules
  (SPEC.md section 5) are not in the schema.
- `spec/fixtures/` — shared `valid/` and `invalid/` manifests every implementation must agree on.
- `spec/examples/moods.taste` — sample file, generated by `python/scripts/build_example.py`.
- `python/src/taste/` — reference library: `container.py` (ZIP reading, atomic writes),
  `validate.py` (schema and section 5 rules), `document.py` (the `Taste` editing API),
  `media.py` (type detection, image sizes and thumbnails via optional Pillow), `cli.py`.
- `js/src/` — `@ruverse/taste`, the TypeScript reader: `zip.ts` (lazy ZIP reading over a Blob),
  `reader.ts` (`TasteFile`), `validate.ts` (a port of the Python validator), `query.ts` (helpers
  shared by viewers), `types.ts`.
- `viewer/` — Taste Viewer (Svelte 5, Vite, Bun). File access goes only through
  `src/lib/platform.ts`, so the planned Tauri desktop builds can swap in native implementations;
  keep it that way. App state is in `src/lib/session.svelte.ts`.

## Rules

- A format change updates, in the same change: `SPEC.md`, `taste.schema.json`, the Python
  validator, fixtures for the new rule, and the example when it should show the feature.
- The Python validator, the TypeScript validator, and the schema must agree on every fixture.
  Invalid fixtures list the exact problem paths in `problems`, and set `schema_catches` honestly.
- The manifest stays plain JSON data in `Taste.manifest`; unknown fields must survive a round trip.
- The library has no required dependencies. Pillow stays optional (`images` extra).
- Writes go through `write_container`, which writes a temporary file and renames it. Never write
  a `.taste` file in place.
- After changing `build_example.py` or anything that changes its output, rerun it and commit the
  regenerated `spec/examples/moods.taste`.

## Checks

From the repository root (TypeScript and the viewer, using Bun):

```bash
bun install
bun run test     # js/ tests, including the shared fixtures
bun run check    # TypeScript and svelte-check
bun run build    # viewer production build
```

For UI changes, look at the viewer at desktop and phone widths in both light and dark OS themes.

From `python/`:

```bash
uv sync --extra dev
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run python scripts/build_example.py   # when the example should change
uv build                                  # when packaging changes
```
